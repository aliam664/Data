# ممیزی فنی و آمادگی انتشار UHM Launcher

تاریخ بررسی: ۲۰۲۶-۰۸-۱۷

> به‌روزرسانی نسخه ۰.۲: رابط پیش‌فرض اکنون Native و مبتنی بر WPF/XAML است. ارجاع‌های HTML/Bridge در بخش‌های پایین این سند مربوط به حالت Legacy هستند و برای مقایسه امنیتی نگه داشته شده‌اند.

## پاسخ کوتاه و بدون ابهام

### آیا با کلیک در رابط گرافیکی می‌توان دانلود را آغاز کرد؟

**از نظر مسیر کد: بله.** دکمه «فقط دانلود» یا «دانلود و نصب» در رابط WPF رویداد Native ایجاد می‌کند؛ `wpf/UHM-Wpf.ps1` مود و مقصد را کنترل، Job را با `New-UhmQueueItem` ثبت و Worker مستقل PowerShell را راه‌اندازی می‌کند. Worker تابع `Invoke-UhmDownload` را اجرا و Progress را در فایل State ثبت می‌کند؛ DispatcherTimer رابط نیز صف را خوانده و درصد، سرعت و وضعیت را نمایش می‌دهد. هیچ درخواست HTTP محلی در مسیر پیش‌فرض وجود ندارد.

**با کاتالوگ فعلی: خیر، دانلود واقعی انجام نمی‌شود.** همه URLهای فعلی عمداً روی `example.com` هستند. این URLها داده نمایشی‌اند و فایل مود واقعی تحویل نمی‌دهند. بنابراین کلیک فعلی فقط صحت اتصال UI به صف را نشان می‌دهد و نهایتاً دانلود با خطای HTTP/HTML مواجه می‌شود.

### آیا با کلیک می‌توان نصب کرد؟

**مسیر نصب پیاده‌سازی شده است، اما پذیرش نهایی Windows هنوز انجام نشده است.** بعد از دانلود کامل، Installer مسیر بازی، Hash، CSP، آرشیو و مسیرهای مقصد را بررسی می‌کند. اگر Overwrite، Script/Executable یا ناسازگاری CSP وجود داشته باشد، UI باید تأیید کاربر را بگیرد. سپس فایل‌ها با Mutex نصب می‌شوند. بازی و Content Manager اجرا نمی‌شوند.

نتیجه مدیریتی:

- پیش‌نمایش و ارزیابی UI: **GO**
- استفاده آزمایشی با فایل‌های کنترل‌شده روی VM: **GO مشروط**
- استفاده روزانه روی نصب اصلی بازی: **NO-GO تا پایان تست Windows**
- انتشار عمومی: **NO-GO تا جایگزینی کاتالوگ Demo و بستن موارد P0**

## مسیر واقعی یک کلیک تا دانلود

```text
کلیک کاربر روی Download در پنجره WPF
  → Routed Click Event در UHM-Wpf.ps1
  → اعتبارسنجی Mod و مقصد Assetto Corsa
  → New-UhmQueueItem
  → ذخیره Job و State محلی
  → Start-UhmNativePendingWorkers
  → powershell.exe UHM-Core.ps1 -Action download-worker
  → Invoke-UhmDownload
  → HTTPS + Redirect امن + Range + .part
  → به‌روزرسانی State
  → DispatcherTimer رابط Native
  → نمایش Progress / Speed / Status
```

این زنجیره Mock نیست؛ رویدادهای WPF مستقیماً به Queue، Downloader و Installer واقعی متصل‌اند. تنها داده Catalog فعلی Demo است. رابط HTML/Bridge صرفاً در حالت `launch-web` باقی مانده است.

## مسیر واقعی دانلود تا نصب

```text
Download کامل
  → بررسی Size و SHA-256
  → New-UhmInstallationPreview
  → بررسی Game Path و CSP
  → استخراج داخل data/cache/staging/<id>
  → ساخت Plan فایل‌به‌فایل
  → تشخیص Overwrite و فایل اجرایی/Script
  → نمایش تأیید در UI
  → POST install-confirm
  → Mutex نصب
  → Copy فایل‌ها بدون اجرای هیچ فایل
  → ثبت installed-mods.json و Manifest
  → پاک‌سازی Staging
```

اگر «نصب پس از دانلود» فعال باشد و هیچ Overwrite، Executable یا هشدار CSP وجود نداشته باشد، نصب می‌تواند بدون مرحله تأیید اضافه ادامه یابد. در سایر موارد وضعیت `awaitingConfirmation` نمایش داده می‌شود.

## ممیزی رابط گرافیکی

### نقاط مناسب

- سلسله‌مراتب منو روشن است و عملیات اصلی در Catalog و Queue متمرکز شده است.
- مود را می‌توان از کارت یا صفحه جزئیات باز کرد.
- مقصد نصب پیش از فعال‌شدن «دانلود و نصب» کنترل می‌شود.
- انتخاب چند مود و «نصب پس از دانلود» در UI وجود دارد.
- وضعیت‌های `queued`، `downloading`، `paused`، `failed`، `downloaded`، `awaitingConfirmation` و `installed` ترجمه و نمایش داده می‌شوند.
- حذف مود در صفحه Installed وجود ندارد و با خواسته پروژه منطبق است.
- در صورت نبود مسیر معتبر، نصب خودکار Disable می‌شود.
- پنجره Native حداقل اندازه امن دارد، قابل Resize/Maximize است و Sidebar در تمام اندازه‌های پشتیبانی‌شده ثابت می‌ماند.

### شکاف‌های UX پیش از انتشار

1. تصاویر فعلی واقعی نیستند؛ Cardها بیشتر از fallback گرافیکی استفاده خواهند کرد.
2. استخراج و ساخت Preview برای آرشیو بزرگ، درصد جداگانه ندارد؛ فقط وضعیت آماده‌سازی نمایش داده می‌شود.
3. ساخت Preview دستی در درخواست Bridge انجام می‌شود و برای آرشیو خیلی بزرگ ممکن است UI تا دریافت پاسخ منتظر بماند. بهتر است این مرحله نیز Worker غیرهم‌زمان و Progress مستقل داشته باشد.
4. گزارش پایان صف به‌صورت وضعیت تک‌تک آیتم‌ها و Log موجود است، اما Summary مجزای «موفق/ناموفق/لغوشده» هنوز بهتر است اضافه شود.
5. Accessibility باید روی Edge با Keyboard-only، Screen Reader و Zoom 200% تست شود.
6. Import امن فایل دانلودشده دستی برای سایت‌های CAPTCHA/Login وجود ندارد.

## ممیزی دانلود

### رفتارهای موجود

- فقط URL مطلق HTTPS پذیرفته می‌شود.
- هر Redirect به‌صورت دستی بررسی و HTTP مسدود می‌شود.
- پاسخ HTTP ناموفق، موفق گزارش نمی‌شود.
- پاسخ HTML به‌عنوان صفحه واسط/دانلود دستی تشخیص داده می‌شود.
- فایل در `.part` نوشته می‌شود.
- Resume از Offset فایل ناقص و `Range` استفاده می‌کند.
- پاسخ Resume باید `206` و Range سازگار داشته باشد.
- فایل نهایی موجود بدون اعتبار Size/Hash جایگزین نمی‌شود.
- Size و SHA-256 در صورت ثبت بررسی می‌شوند.
- Cancel به‌طور پیش‌فرض فایل ناقص را نگه می‌دارد.

### محدودیت‌ها

- اگر Server از Range پشتیبانی نکند، Resume ممکن نیست و شروع دوباره نیازمند تأیید حذف `.part` است.
- Cancel نمی‌تواند یک Read شبکه‌ای که در سطح سیستم‌عامل کاملاً Hang شده است فوراً قطع کند؛ Timeout/قطع Process راه نهایی است.
- CAPTCHA، Login، Cookie و لینک‌های JavaScript قابل دانلود خودکار نیستند.
- صحت مود بدون SHA-256 فقط بر اساس Size قابل بررسی است؛ برای Production ثبت Hash توصیه الزامی است.

## ممیزی استخراج و نصب

### کنترل‌های موجود

- مسیر مطلق، UNC، Drive، `..`، ADS، Device Name و کاراکترهای نامعتبر رد می‌شوند.
- ZIP به‌صورت Entry-by-Entry داخل Staging استخراج می‌شود.
- RAR/7Z ابتدا List و سپس Extract می‌شوند.
- TAR link و Reparse Point بررسی می‌شوند.
- هیچ EXE، CMD، BAT، PowerShell، VBS، JS یا MSI اجرا نمی‌شود.
- تمام مقصدها با `GetFullPath` زیر Game Root محصور می‌شوند.
- نگاشت‌های رایج `content/cars`، `content/tracks`، `cars`، `tracks`، Wrapper و ریشه‌های گرافیکی پشتیبانی می‌شوند.
- دو Source که به یک Destination نگاشت شوند رد می‌شوند.
- نصب با Mutex سریال می‌شود.

### ریسک‌های باقی‌مانده

1. سقف قطعی برای **حجم استخراج‌شده** همه فرمت‌ها وجود ندارد؛ Archive Bomb باید با مجموع Uncompressed Size و فضای آزاد Disk کنترل شود.
2. بررسی Symlink در 7Z/RAR باید پیش از Extract بر اساس خروجی `7z l -slt` کامل‌تر شود؛ بررسی پس از Extract به‌تنهایی برای مدل تهدید سخت‌گیرانه کافی نیست.
3. ساختار آرشیوهای Content Manager بسیار متنوع است و الگوریتم فعلی همه Wrapperهای غیرمعمول را تضمین نمی‌کند.
4. Rollback تراکنشی وجود ندارد؛ خطای Disk/Permission وسط Copy می‌تواند نصب جزئی ایجاد کند.
5. DLL کپی‌شده اجرا نمی‌شود، اما ممکن است در اجرای بعدی توسط خود بازی Load شود. Catalog و Hash باید قابل اعتماد باشند.

## ممیزی Local Bridge

### نقاط مثبت

- Listener روی `localhost` است و IP مبدأ باید Loopback باشد.
- پورت و Token در هر اجرا تصادفی‌اند.
- Token در Fragment اولیه URL است و وارد Request/Log اولیه نمی‌شود.
- API علاوه بر Token، Host و Origin/Referer/Sec-Fetch-Site را کنترل می‌کند.
- CORS فعال نیست و CSP، `nosniff` و `frame-ancestors none` ارسال می‌شوند.
- Body و نرخ درخواست محدود شده‌اند.
- Password کاتالوگ پیش از ارسال به UI حذف می‌شود.
- Heartbeat و خروج امن برای توقف Bridge وجود دارد.

### محدودیت‌ها

- توقف پس از بستن پنجره فوری و قطعی نیست و به timeout حدود ۹۰ ثانیه وابسته است.
- برخی سیستم‌های سازمانی ممکن است HttpListener یا Loopback را با Policy/Firewall محدود کنند.
- Catalog امضای دیجیتال مستقل ندارد؛ امنیت آن به HTTPS، GitHub و کنترل حساب مخزن وابسته است.

## موارد P0 پیش از اینکه بگوییم «با یک کلیک واقعاً آماده استفاده عمومی است»

1. جایگزینی تمام `example.com`ها با لینک‌های رسمی و مجاز، Size دقیق و SHA-256.
2. اجرای ۳۰ سناریوی `tests/TEST-PLAN.md` روی Windows 10 و Windows 11.
3. تست یک سرور HTTPS کنترل‌شده برای Redirect، Range، قطع اتصال، Resume و پاسخ HTML.
4. تست ZIP/RAR/7Z/TAR سالم و مخرب با 7-Zip واقعی.
5. افزودن سقف Uncompressed Size، بررسی فضای Disk و سخت‌گیری Symlink برای 7Z/RAR.
6. تبدیل Install Preview دستی به Job غیرهم‌زمان با Progress.
7. تست نصب خودرو، پیست، اسکین، App و پک گرافیکی روی Game Root مصنوعی و سپس VM.
8. ثبت Hash برای Catalog Production و Review دوباره لینک‌های پولی/مجوزها.
9. امضای Code Signing برای فایل‌های CMD/PowerShell یا حداقل انتشار Hash رسمی Release.
10. اجرای Workflow ویندوز و رفع همه خطاهای Pester/Parser پیش از Tag نسخه.

## جمع‌بندی

معماری کلی درست و شدنی است و کلیک UI واقعاً به Downloader و Installer متصل شده است؛ این پروژه صرفاً یک طرح تصویری HTML نیست. با این حال، **نسخه موجود هنوز لانچر Production با دانلود واقعی نیست**، زیرا کاتالوگ Demo است و آزمون E2E روی Windows انجام نشده است. پس از انجام موارد P0 می‌توان با اطمینان گفت کاربر روی کارت مود کلیک می‌کند، فایل واقعی دانلود می‌شود، Preview امن می‌بیند و نصب انجام می‌گیرد.
